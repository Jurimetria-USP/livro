13  Limpeza e estruturação de dados jurídicos

Do registro inicial ao banco analisável

13.1 Introdução

Uma base de dados não está pronta para análise apenas porque pode ser aberta no R. Categorias equivalentes podem estar registradas com grafias diferentes, respostas múltiplas podem ocupar várias colunas e valores monetários podem combinar números, textos e ausências. Antes de calcular frequências ou medidas estatísticas, precisamos conhecer a estrutura dos registros e documentar as decisões necessárias para torná-los comparáveis.

Neste capítulo, trabalharemos com uma base composta por 700 casos inteiramente sintéticos sobre violência de gênero digital. Nenhuma linha corresponde a um processo, uma pessoa ou uma decisão real. Cada linha representa um caso simulado e cada coluna registra uma característica do caso, das provas ou da decisão judicial.

NotaObjetivos do capítulo

Ao final do capítulo, você deverá ser capaz de:

  • inspecionar a estrutura de uma base de dados;
  • identificar categorias inconsistentes e valores ausentes;
  • documentar decisões de limpeza;
  • padronizar variáveis categóricas;
  • estruturar respostas múltiplas como indicadores binários;
  • distinguir zero, ausência e registros monetários textuais;
  • validar o banco resultante antes da análise.

13.2 Como a base foi construída

A base foi gerada especificamente para o percurso didático deste livro. O processo de simulação começou pela criação de 700 identificadores fictícios e pela atribuição probabilística de tribunal, ano, perfil da vítima, perfil do agressor, participação da plataforma, provas, suficiência probatória, contestação, resultado e valor da indenização.

As relações entre as variáveis também foram planejadas. Por exemplo, a suficiência probatória depende parcialmente da quantidade de provas e da existência de contestação. O resultado da primeira instância se relaciona à suficiência, enquanto o valor positivo da indenização varia conforme características simuladas do caso. Essas relações permitem que as análises posteriores encontrem padrões interpretáveis, sem reproduzir observações ou resultados individuais de uma pesquisa real.

Depois de criar uma estrutura coerente, foram introduzidos deliberadamente problemas comuns em bases jurídicas: grafias diferentes para a mesma categoria, anos registrados como texto, respostas múltiplas distribuídas em várias colunas, repetição de uma prova no mesmo caso, ocorrência simultânea de Não cita e uma prova identificada, valores monetários em formatos diferentes e indenizações expressas em salários mínimos.

O arquivo inicial contém apenas as 14 variáveis necessárias ao exercício. O objetivo não é reconstruir uma pesquisa empírica específica, mas oferecer um banco seguro e reproduzível no qual cada decisão de limpeza possa ser inspecionada e justificada.

NotaO banco didático

O arquivo utilizado no livro contém somente as 14 variáveis necessárias ao percurso didático deste capítulo. Os casos receberam códigos sequenciais inteiramente fictícios. Como não existem registros processuais subjacentes, o banco não deve ser interpretado como fonte de resultados substantivos sobre violência de gênero digital. Sua finalidade é ensinar decisões de limpeza, estruturação e análise.

13.6 Decidir antes de transformar

O processo de limpeza adotado neste capítulo seguirá uma sequência comum para cada variável:

  1. listar os valores existentes;
  2. calcular suas frequências;
  3. identificar diferenças de grafia e significado;
  4. definir e justificar a regra de tratamento;
  5. criar uma nova variável sem apagar o registro inicial;
  6. conferir o resultado da transformação.

As próximas seções aplicarão esse procedimento ao tribunal, ao ano da decisão, ao perfil da vítima, ao perfil do agressor, à participação das plataformas, às provas, à suficiência probatória, à decisão de primeira instância e aos valores de indenização.

O objeto base_limpa parte de uma cópia da base inicial. Cada seção acrescentará a ele as variáveis tratadas, preservando os registros originais. Desse modo, o banco final será o resultado acumulado e reproduzível de toda a sequência de limpeza.

13.9.1 Criando a variável tratada

Preservamos Vítima: e criamos perfil_vitima. Essa prática mantém o registro recebido e permite conferir a transformação.

base_limpa <- base_limpa |>
  mutate(
    perfil_vitima = case_when(
      tolower(trimws(`Vítima:`)) %in% c(
        "mulher",
        "mulheres"
      ) ~ "Mulher",

      tolower(trimws(`Vítima:`)) %in% c(
        "homem",
        "homens",
        "homem (backlash)"
      ) ~ "Homem",

      tolower(trimws(`Vítima:`)) %in% c(
        "homem e mulher",
        "homens e mulheres"
      ) ~ "Homem e mulher",

      tolower(trimws(`Vítima:`)) == "não cita" ~ "Não informado",
      is.na(`Vítima:`) ~ "Não informado",
      TRUE ~ "Revisar"
    )
  )

A categoria Revisar evita que valores inesperados sejam incorporados silenciosamente a um grupo. Se a fonte for atualizada e passar a conter uma nova categoria, ela permanecerá visível até que seu significado seja examinado.

13.16.1 Identificando a forma de registro

Criamos forma_registro_valor para documentar como o valor numérico foi obtido:

  • Valor informado em reais: o banco já apresenta um valor numérico;
  • Convertido de salários mínimos: o registro informa uma quantidade de salários mínimos;
  • Não informado: o campo está vazio ou contém Não consta.
converter_numero_br <- function(x) {
  vapply(
    x,
    function(valor) {
      if (is.na(valor)) {
        return(NA_real_)
      }

      texto <- gsub("R$", "", valor, fixed = TRUE)
      texto <- gsub(" ", "", texto, fixed = TRUE)

      if (grepl(",", texto, fixed = TRUE)) {
        texto <- gsub(".", "", texto, fixed = TRUE)
        texto <- sub(",", ".", texto, fixed = TRUE)
      } else if (grepl(
        "^[0-9]{1,3}(\\.[0-9]{3})+$",
        texto
      )) {
        texto <- gsub(".", "", texto, fixed = TRUE)
      }

      suppressWarnings(as.numeric(texto))
    },
    numeric(1)
  )
}

Valores monetários de anos diferentes não são diretamente comparáveis, pois o poder de compra da moeda se altera ao longo do tempo. DicaComo calcular a atualização monetária

O fator de atualização corresponde à razão entre o índice do período de destino e o índice do período de origem:

\[ \text{Fator de atualização} = \frac{\text{IPCA de julho de 2026}} {\text{IPCA de julho do ano de referência}} \]

O valor atualizado é obtido multiplicando o valor nominal por esse fator:

\[ \text{Valor em julho de 2026} = \text{Valor nominal} \times \frac{\text{IPCA de julho de 2026}} {\text{IPCA de julho do ano de referência}} \]

Por exemplo, para atualizar R$ 10.000,00 de julho de 2015:

\[ 10\,000 \times \frac{7\,657{,}73}{4\,337{,}11} = 17\,656{,}30 \]

Portanto, R$ 10.000,00 de julho de 2015 correspondem aproximadamente a R$ 17.656,30 em valores de julho de 2026.

Incorporamos os índices à base e calculamos o fator de atualização:

import numpy as np
import pandas as pd

coluna_valor = (

texto_valor = base_limpa["valor_indenizacao_original"]

def converter_numero_br(valor):
    if pd.isna(valor):
        return np.nan

    texto = str(valor).replace("R$", "").replace(" ", "")

    if "," in texto:
        texto = texto.replace(".", "").replace(",", ".")
    elif pd.Series([texto]).str.match(
        r"^[0-9]{1,3}(\.[0-9]{3})+$"
    ).iloc[0]:
        texto = texto.replace(".", "")

    return pd.to_numeric(texto, errors="coerce")

valor_extraido = texto_valor.apply(converter_numero_br)

base_limpa["forma_registro_valor"] = np.select(
    [
        texto_valor.isna() | texto_valor.eq("Não consta"),
        texto_valor.str.contains(
            "salários mínimos",
            na=False,
            regex=False
        ),
        valor_extraido.notna()
    ],
    [
        "Não informado",
        "Convertido de salários mínimos",
        "Valor informado em reais"
    ],
    default="Revisar"
)

    "ano_decisao": list(range(2010, 2026)),
    "salario_minimo": [
        510, 545, 622, 678, 724, 788, 880, 937,
        954, 998, 1045, 1100, 1212, 1320, 1412, 1518
    ]
})

base_limpa["valor_extraido"] = valor_extraido
base_limpa["quantidade_salarios_minimos"] = pd.to_numeric(
    texto_valor.str.extract(r"^([0-9]+(?:[.,][0-9]+)?)")[0]
    .str.replace(",", ".", regex=False),
    errors="coerce"
)

    salario_minimo,

    [
        base_limpa["forma_registro_valor"].eq(
            "Valor informado em reais"
        ),
        base_limpa["forma_registro_valor"].eq(
            "Convertido de salários mínimos"

    ],

        base_limpa["valor_extraido"],
        base_limpa["quantidade_salarios_minimos"] *
        base_limpa["salario_minimo"]

13.18 Síntese

A construção de um banco analisável exige decisões substantivas e técnicas. O banco final não é um arquivo independente de sua história de construção. Ele é o resultado reproduzível das regras apresentadas ao longo do capítulo e será o ponto de partida para a análise descritiva.
